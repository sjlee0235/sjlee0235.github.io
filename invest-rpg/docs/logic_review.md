# 게임 규칙 검토

시뮬레이션과 코드 검토로 찾은 점과, 그에 대한 기획 결정을 기록한다.
- **A**: 검토에서 고친 것 (결정 결과 포함)
- **B**: 결정이 필요한 것 — 결정된 것과 아직 답을 기다리는 것
- **C**: 확인했고 문제없는 것

---

## A. 고친 것

### A1. 뉴스를 보고 5초 안에 사면 무조건 이기는 문제 → "발표 즉시 75% 반영" — ✅ 승인
- **문제**: 뉴스가 뜬 뒤 5초 동안은 옛 가격 그대로라, 그 사이에 호재 종목을 사면 영향 전부를 공짜로 얻었다. 시뮬레이션에서 시대당 **+536%**(몰빵 +889%).
- **변경**: 기존 "5초 뒤 100% 반영" → **발표 즉시 75% + 5초 뒤 25%** (`INSTANT_REACTION_SHARE = 0.75`).
- **결과**: 초고속 추종 +63%(목표 +30~80%), 사람형 몰빵 +75%.
- 기획자 승인으로 확정 규칙이 되었다 (README 4장, 5장 25번).

### A2. 잠정 뉴스 단서 확률 — ✏️ 70% → 65% (기획 결정)
- 시뮬레이션 보정으로 70%까지 올렸으나, 기획 결정으로 **65%** (`LEAN_PROB = 0.65`).
- 이유: 한 판에 같은 스토리는 한 번뿐이라 큰 수의 법칙이 약하게 작용한다. 확신보다 **분산 투자**를 고르게 하려는 의도.
- 잠정 정방향 목표를 +40~120% → **+25~100%**로 낮췄다. 현재 +34% (5번 평균).
- 분산 점검: 잠정 분산(가용 자금 20~30%를 3종목에) 중앙값 +8.8%, 큰 손실(<-50%) 0%. 잠정 몰빵 중앙값 +39%, 큰 손실 3.2%. → 분산이 큰 손실 확률을 크게 줄인다 (기대대로).

### A3. 분위기 편향(콘텐츠 작성 가이드) 65% → 75% — 유지
- 65%에서는 분위기 전략이 목표 하한(+5%)에 못 미치는 판이 있었다. 75%에서 +11% (5번 평균).
- 분위기 전략과 잠정 정방향이 목표 하한 근처인 점은 **단계 B 실제 데이터로 다시 확인**한다.

### A4. 세이브 불러오기로 "다시 하기"가 되던 허점 — 보강 완료
- 1차: 세이브에 지금 틱과 이번 시대 행동을 담고, 불러올 때 리플레이로 그 순간 그대로 이어 한다.
- 2차 보강(기획 요청)
  - **저장 빈도**: 매매·입금·뉴스 발표·백그라운드 전환·30초마다·시대 종료 때 엔진이 "저장 필요"를 알린다 → 강제 종료 후 되돌아가는 시간이 최대 30초.
  - **버전 고정**: 세이브에 엔진 버전·콘텐츠 버전(시대 데이터 지문)·밸런스 지문과 상태 스냅샷(틱, 종목 현재가, 계좌·보유 종목, 즐겨찾기, 수익률 진행)을 담는다.
    버전이 같으면 리플레이로 이어 하기(`resumed`), 다르면 스냅샷 가격으로 그 시대를 자동 정산하고 다음 시대부터 새 버전 적용(`settled_on_version_change`).

### A5. 플레이 중 정보가 새는 구멍 — 공개용 뷰로 차단 (기획 결정 반영)
- 엔진이 화면에 주던 데이터에 뉴스의 영향 테마·방향, 테마 분위기·비중이 들어 있었다.
- 화면은 **공개용 뷰(`PublicGame`)만** 받는다. 뉴스: id·종류·제목·본문·발표 시각(+결과 뉴스만 가상 시나리오 태그). 종목: 무작위 id·이름·설명·가격·즐겨찾기.
- 종목 목록은 즐겨찾기 먼저 + 이름 가나다순, 종목·뉴스 id는 판마다 바뀌는 무작위 문자열 → 저장 순서·id로 정답을 짐작할 수 없음 (시드 1,000개 테스트).
- 시대가 끝난 뒤에만 `getEraDebrief()`로 분위기·비중, 단서와 실제 결과, 역사 여부, 해설 전체를 공개.
- 콘텐츠 금지어 점검 추가: 종목명 형식·평가 어감 단어, 종목 설명의 전망 표현, 뉴스의 주가 방향 표현.

### A6. 수익률 공식 → 시간가중수익률(TWR) (기획 결정 반영)
- 이전 공식 (최종 자산 − 시작 자금) ÷ 시작 자금 은 시대 중간 입금(인형 눈 붙이기·결제·광고 보상)을 수익으로 세었다.
  (예전 연습 모드 시절의 "광고 보상을 뺀 수익률" 공식도 이것으로 대체한다.)
- 입금 시점마다 구간을 나눠 구간 수익률(구간 끝 자산 ÷ 구간 시작 자산 − 1)을 곱한다. 입금이 없으면 단순 수익률과 같다.
- 정산: 수익률(TWR), 순손익(입금 제외), 출처별 입금, 종료 자산. 누적 수익률 = 시대별 TWR의 곱.

## C. 확인했고 문제없는 것

- 같은 시드 → 같은 결과 (기록을 붙여도, 공개용 뷰로 봐도 결과가 같음, 리플레이 = 원래 결과)
- 임의의 틱에서 저장 → 불러오기 = 끊김 없이 진행한 결과 (시드 3개 × 저장 시점 9곳, 상태 지문 비교)
- 뉴스 사이 ±30% 한도: 즉시 반영 + 5초 뒤 반영을 합쳐도 넘지 않음
- 시대 시작 추첨: 3회 안에 99.8% 성공, 추첨 조합(core 수)에 따른 수익 차이는 몇 %p 수준
- 결과 뉴스가 단서대로 나온 비율: 설정 65% ↔ 실측 약 60~70%
- `INDIRECT_EXTRA_DELAY_TICKS`(간접 영향 늦게 반영)는 켜면 반영 뒤에 사도 이익이 나는 허점 → **계속 꺼 둔다**
- `ORDER_DELAY_TICKS`(주문 지연)는 A1로 필요 없어졌다 → 꺼 둔다
- 수수료 0.2%는 그대로 둬도 지연 추종이 목표 안에 들어온다
