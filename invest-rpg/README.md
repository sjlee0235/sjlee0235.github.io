# 투자 RPG (가제)

모바일(iOS/Android)용 2D 픽셀 RPG풍 투자 시뮬레이션 게임.
감으로 투자하다 전 재산을 잃은 20대 후반 청년이 공부하고, 인형 눈 붙이기로 모은 1만 비트로 다시 시작하는 이야기.

**현재 단계: W1 — 게임 규칙 엔진** (화면·그림·결제·광고·서버 없음)
- 단계 A(엔진·스키마·테스트·시뮬레이션·점검 스크립트) 완료
- 단계 A 보완: 5번 반복 시뮬레이션으로 밸런스 조정, 규칙 검토(`docs/logic_review.md`), 플레이 데이터 수집 구조(`docs/telemetry.md`)
- 단계 B(2000년대 콘텐츠 재작성) 대기 중 → 그 전까지 `ALL_ERAS`는 비어 있다. 데모·시뮬레이션은 기획 조건을 흉내 낸 **가상 시대**로 돈다.

---

## 1. 실행 방법

1. [Node.js](https://nodejs.org) **22.18 이상** 설치 (Node.js = 컴퓨터에서 타입스크립트를 실행해 주는 프로그램)
2. `cd invest-rpg && npm install`

| 명령 | 하는 일 |
|---|---|
| `npm test` | 자동 테스트 전체 |
| `npm run sim` | 밸런스 시뮬레이션 (전략 8개 + 참고 2개 × 시드 200개, 약 1분). `npm run sim -- 50`으로 빠르게 |
| `npm run sim:repeat` | 반복 시뮬레이션: 서로 다른 가상 데이터·시드로 5번 × 200판, 평균과 목표 판정 (약 1분) |
| `npm run telemetry:report` | 플레이 기록 분석 리포트 (봇 기록으로 점검, 또는 `-- 기록.jsonl`) |
| `npm run lint:content` | 콘텐츠 작성 가이드 점검 (영향 테마 수, 영향도 공식, 해설 누락, 분위기 편향 등) |
| `npm run demo` | 한 시대를 터미널에서 끝까지 (뉴스·해설 알림 출력). `npm run demo -- 7`은 시드 7 |
| `npm run demo -- tutorial` | 튜토리얼 흐름 |
| `npm run check` | 타입 검사 + 테스트 |

### 화면(W2 이후)에서 엔진을 쓰는 법

```ts
const game = new Game({ eras: ALL_ERAS, seed, telemetry: sink });   // 시대 시작 때 테마 20개 추첨 (game.draw). sink는 선택

// 화면 쪽 타이머가 5초마다 호출. 뉴스가 떠도 시간은 멈추지 않는다.
const r = game.advanceTick();
if (r.advanced && r.news) showNews(game.getNewsPopup(r.news));   // 관련 테마(강도), isHistorical(가상 시나리오)
if (r.advanced) animate(r.changes, r.instantChanges);            // instantChanges = 뉴스 발표 순간 바로 반영된 몫
if (r.advanced) r.recaps.forEach(showRecap);                     // 발표 120초 뒤 해설 알림
if (r.advanced && r.settlement) showSettlement(r.settlement);

game.getNewsArchive();             // 보관함: 뉴스 + 태그(breaking/tentative/outcome) + 강도 + 해설 알림
game.suspend(); game.resume();     // 앱이 백그라운드로 갈 때
game.startNextEra();               // 다음 시대 (자금 이월)

// 화면 이벤트 기록 (docs/telemetry.md)
game.track('news_popup', { newsId, dwellMs, closedBy: 'confirm' }, Date.now());

// 세이브
const save = saveGame(createSaveData(), game);      // 시드·시대 순번·시작 자금·추첨 결과 + 지금 틱·이번 시대 매매
const restored = restoreGame(save, ALL_ERAS);       // 저장한 순간 그대로 이어 하기

// 튜토리얼 (첫 진입 때 한 번)
const tut = new TutorialSession();                  // tut.stage: waiting → reading → reaction → recap → done
```

## 3. 데이터 구조

### 테마 (시대마다 풀 36개, 테마당 종목 1개)
```jsonc
{ "id": "semiconductor", "name": {"ko": "...", "en": "..."},
  "sentiment": "positive",        // positive 13 / negative 13 / neutral 10
  "relevance": "core",            // core 24 : peripheral 12 (분위기와 독립)
  "keywords": { "ko": ["반도체", "메모리", ...], "en": [...] },   // 5~8개
  "existsEvidence": "그 시대에 존재했다는 근거 한 줄 (모르면 '확인 필요')" }
```
- 비주류(peripheral) 테마는 주로 시장 전체 뉴스·간접 영향으로 움직이는 '배경 종목'이다. 뉴스 풀 전체에서 최소 2회는 영향 대상이어야 한다.
- 풀 크기는 코드에 고정하지 않고 데이터에서 읽는다.

### 뉴스
```jsonc
{ "id": "...", "type": "breaking",   // breaking(속보) / tentative(잠정) / outcome(결과)
  "magnitude": 7,                     // 뉴스 규모: 속보 3~9, 잠정 1~3, 결과 7~9 위주
  "title": {...}, "body": {...},      // 본문에 연도·월 표기 금지
  "effects": [{
    "themeId": "refining", "impact": 7,
    "link": { "strength": 3,          // 3 직접 / 2 밀접 / 1 간접
              "keywords": [{ "newsTerm": "유가", "themeTerm": "정유" }],
              "chain": "강도 2·1일 때 연결 설명" },
    "reason": { "ko": "해설 알림용 한 줄 이유" },   // 영향도 절댓값 상위 4개는 한국어 필수
    "adjustNote": "공식에서 ±1 조정했을 때 이유" }],
  "realDate": "2008-07-11",           // 근거 확인용 메타데이터
  "reactionNote": {...} }             // 결과 뉴스가 반대로 반응할 때 (실제 기록 근거가 있을 때만)
```
- **영향도 공식**: `|impact| = max(1, round(magnitude × 계수))`. 계수는 강도 3 → 1.0, 2 → 0.6, 1 → 0.3이고, 부호는 호재/악재다.
- 영향 테마 6~9개. 호재와 악재를 섞는다. 분위기 편향(긍정 테마 호재 약 **75%**, 부정 테마 악재 약 75%, 중립 50%)을 맞춘다. (65% → 75%, 6장)
- 종류(direct/indirect)는 따로 적지 않고 강도에서 계산한다 (3 → direct, 2·1 → indirect).

### 스토리 (잠정 → 결과)
```jsonc
{ "id": "...", "tentative": { /* 잠정 뉴스 */ },
  "news": [ /* 결과 2개 (+ 단서) */ ],
  "outcomes": [ { "newsId": "A", "isHistorical": true }, { "newsId": "B", "isHistorical": false } ],
  "leansTo": "A",                    // 잠정 뉴스 본문의 단서가 가리키는 결과
  "clues": [ { "newsId": "...", "pointsTo": "A" } ] }   // 선택
```
- 결과는 **항상 서로 반대인 2개**다 (공통 테마의 부호가 반대). 검사기가 확인한다.
- 결과는 그때그때 추첨한다. 단서(`leansTo`)대로 **70%**, 반대로 30%다 (6장 참고).
- 추천: 단서 쪽 결과를 실제 역사(`isHistorical: true`)로 맞춘다 (`docs/logic_review.md` B5).
- 잠정 뉴스 본문은 결과를 확정처럼 쓰지 않고, 판단 단서가 읽히게 쓴다.

## 4. 확정된 규칙

| 항목 | 값 |
|---|---|
| 상수 | `TICK_SECONDS=5`, `MAX_TICK_MOVE=1.5`, `WINDOW_TICKS=12`, `WINDOW_CAP=3.0`, `NEWS_REACTION_TICKS=1`, `INERTIA_TICKS=2`, `INERTIA_PROBS={50,25,25}`, `NEWS_BAND_PCT=30`, `P_START_STORY=0.85`, `LEANS_TO_CHANCE=0.7`, `INSTANT_REACTION_SHARE=0.75` |
| 시간 | 시대당 2시간(1,440틱), 차트 20분(240개), 게임 모드는 하나(실전) |
| 시대 시작 추첨 | 테마 풀에서 20개 (긍정 7 / 부정 7 / 중립 6), core 11개 이상, 속보 10·스토리 8 이상 사용 가능해야 함 (최대 50회 재추첨) |
| 일반 변동 | 틱당 -1.5~+1.5%, 1분 누적 ±3%, 넘치면 반사 |
| 뉴스 시점 | 첫 뉴스 1~3분, 이후 4~7분 간격 (시대당 평균 약 22개, 최대 30슬롯) |
| 뉴스 구성 | 슬롯 기준 속보 약 1/3, 잠정 약 1/3, 결과 약 1/3 |
| 뉴스 반영 | 발표(틱 k) **순간 75%** → **틱 k+1(5초 뒤)에 나머지 25%** → k+2·k+3 관성 (같은 방향 50 / 반대 25 / 변동 없음 25) |
| 반영률 | 영향도 × 3% × 배율 (강도 3: 0.6~1.4, 강도 2·1: 0.4~1.6), ±30%로 자름 |
| 뉴스 사이 한도 | 발표 시점 가격 P0 기준, 다음 뉴스 전까지 [0.7×P0, 1.3×P0] (모든 움직임 포함) |
| 해설 알림 | 발표 120초 뒤, 반영률 상위 3종목 + 나머지 개수, 시간을 멈추지 않음 |
| 수수료 | 매수·매도 각 0.2% |
| 수익률 | (최종 자산 − 시작 자금) ÷ 시작 자금 × 100 |
| 튜토리얼 | 첫 진입 한 번. 뉴스 1개 → 매수 → 반영 확인 → 해설 알림. 이때만 뉴스가 뜨면 시간 정지 |
| 기본 OFF 옵션 | `ORDER_DELAY_TICKS=0`(주문 N틱 뒤 체결), `INDIRECT_EXTRA_DELAY_TICKS=0`(간접 영향 N틱 늦게) |

## 5. 가정한 규칙 (바꾸고 싶으면 알려주세요)

표시: 🆕 이번에 새로 정함 · ✏️ 이번에 바뀜 · (표시 없음) 전과 같음

### 시대 시작 추첨
1. 🆕 분위기 그룹마다 따로 섞어서 앞에서부터 뽑는다(층화 추첨). 재추첨 시드는 원래 시드에서 시도 번호로 만든다.
2. 🆕 50회 안에 조건을 못 맞추면 "core 조건 충족 → 속보·스토리 충족 정도" 순으로 가장 나은 추첨을 쓰고, `draw.warning`에 경고를 남긴다.
3. 🆕 스토리는 잠정 뉴스와 결과 2개가 모두 유효(유효 영향 테마 3개 이상)해야 쓴다. 유효하지 않은 **단서** 뉴스는 빼고 스토리는 그대로 쓴다.
4. 🆕 이번 판에서 뉴스의 영향은 활성 테마 것만 남긴다. 화면에 보이는 '관련 테마'도 활성 테마만이다.

### 뉴스 일정
5. 🆕 **구성 비율 해석**: 빈 슬롯마다 진행 중인 스토리가 없으면 85% 확률로 새 잠정 뉴스를 시작하고, 아니면 속보를 넣는다. 잠정과 결과 사이의 빈 슬롯은 속보로 채워진다. 그래서 슬롯 기준 **속보 약 33%, 잠정 약 33%, 결과 약 33%**가 된다 (시뮬레이션 200판 평균 34%). 기획의 "속보 : 잠정 = 1 : 2"를 이렇게 해석했다.
6. 🆕 속보가 바닥나면 스토리를, 스토리가 바닥나면 속보를 넣는다. 둘 다 없으면 그 슬롯은 비운다(반복 없음).
7. 🆕 단서 뉴스는 실제로 뽑힌 결과를 가리키는 것만, 잠정과 결과 사이 빈 슬롯에 나온다. 단서도 슬롯 하나를 차지한다.
8. 🆕 결과가 가상 시나리오(`isHistorical:false`)면, 그 결과를 가리키는 단서도 가상으로 표시한다.
9. 마지막 뉴스는 반영·관성이 시대 안에서 끝나는 시점까지만 뜬다.

### 가격
10. 🆕 **뉴스 사이 한도의 기준가(P0)**는 뉴스가 발표되면 **모든 종목**에서 그 순간 가격으로 다시 잡힌다 (영향받지 않은 종목 포함).
11. 🆕 한도 계산은 정수 가격 기준이다: 하한 = 올림(0.7×P0), 상한 = 내림(1.3×P0). 반올림 때문에 넘지 않도록 가격도 이 범위로 맞춘다.
12. 🆕 일반 변동은 1분 한도와 뉴스 사이 한도를 **둘 다** 만족하도록 반사한다 (두 범위 모두 0을 포함해서 항상 가능).
13. 🆕 뉴스 반영이 한도에 막혀 0%가 되어도, 관성 방향은 원래 반영 방향을 따른다.
14. ✏️ 관성 크기는 0.1~1.5%이고 1분 한도에서 제외한다. 뉴스 사이 한도 안으로만 반사한다.

### 해설 알림·보관함
15. 🆕 해설 알림의 종목은 이번 판 활성 종목 중 그 뉴스로 실제 반영이 일어난 종목이다. 반영률 절댓값 순 상위 3개를 보여준다 (0%로 막힌 종목도 개수에 포함).
16. 🆕 `reason`이 없는 항목은 자동 문구 재료(`auto`: 뉴스 단어, 테마 이름, 수혜/부담)를 넘긴다. 문구는 i18n `recap.auto`로 만든다.
17. 🆕 해설 알림 시점이 시대 마지막 틱(2:00:00)과 같으면 만들고, 넘으면 만들지 않는다.

### 기타
18. 🆕 튜토리얼은 5분짜리 판이다 (뉴스 30초, 해설 알림 2분 30초). 뉴스로 시간이 멈춘 동안에도 매매할 수 있다 ("매수" 단계).
19. ✏️ 세이브는 시드·시대 순번·그 시대 시작 자금·추첨 결과에 더해 **지금 틱·이번 시대 매매·관심 종목·엔진 버전**을 담는다. 불러오면 같은 시드로 매매를 다시 넣으며 저장한 틱까지 빨리 돌려 그대로 이어 한다. 엔진 버전이 다르면 그 시대를 **새 시드로** 처음부터 (같은 추첨·같은 시작 자금). 이전 방식은 같은 시드로 처음부터 다시 시작해서, 이미 본 뉴스를 알고 다시 할 수 있었다.
20. 🆕 주문 지연 옵션을 켜면 주문은 접수만 되고 N틱 뒤 그 틱의 가격으로 체결된다. 그때 현금이 부족하면 체결이 실패한다.
21. 평균가는 이동평균, 수수료는 내림이며 매입원가에 포함, 구입 순서 보존, 매수 시 즐겨찾기 자동 추가.
22. 🆕 **발표 즉시 몫**: 종목별 반영률을 0.1% 단위로 75%(0 쪽으로 버림)와 나머지로 나눈다. 나머지가 0이 되면 관성이 생기지 않으므로 최소 ±0.1%는 5초 뒤 몫으로 남긴다. 즉시 몫은 틱을 진행하지 않고 가격만 옮기며, 1분 한도·관성과 무관하다. ±30% 한도의 기준가는 즉시 몫 반영 **전** 가격이다.
23. 🆕 튜토리얼에서도 즉시 몫은 뉴스가 뜨는 순간(시간 정지 전) 반영된다. 그래서 정지 중에 사면 5초 뒤 몫만 얻는다는 것을 보여 준다.
24. 🆕 플레이 기록은 `telemetry` 옵션을 줄 때만 남고, 붙여도 게임 결과는 같다. 매매 순간 상황(최근 뉴스와 지난 틱, 이 종목과 뉴스의 연결, 진행 중 스토리 등)을 함께 기록한다 (`docs/telemetry.md`).

## 6. 밸런스 시뮬레이션 (가상 시대 — 단계 B 후 실제 데이터로 다시 측정)

### 5번 반복 시뮬레이션 (`npm run sim:repeat`)
서로 다른 가상 시대 데이터 5개 × 게임 시드 200개씩, 전략별 **중앙값**과 그 평균. 수수료 0.2% 포함.

| 전략 | 1회 | 2회 | 3회 | 4회 | 5회 | **평균** | 목표 | 판정 | 손해 본 판 |
|---|---|---|---|---|---|---|---|---|---|
| 무작위 매매 | -6.8% | -6.2% | -5.8% | -5.2% | -5.9% | **-6.0%** | -10 ~ +5% | ✅ | 72% |
| 균등 매수 후 보유 | +0.5% | -0.7% | -2.0% | -5.9% | -3.8% | **-2.4%** | -10 ~ +20% | ✅ | 61% |
| 지연 추종 | +2.9% | +0.0% | +5.1% | +2.2% | +3.9% | **+2.8%** | -5 ~ +15% | ✅ | 46% |
| 초고속 추종 | +69.9% | +72.9% | +67.2% | +69.4% | +72.2% | **+70.3%** | +30 ~ +80% | ✅ | 3% |
| 분위기 전략 | +15.6% | +15.2% | +4.7% | +5.9% | +18.0% | **+11.9%** | +5 ~ +40% | ✅ | 18% |
| 역분위기 | -22.1% | -17.6% | -11.3% | -15.2% | -14.6% | **-16.2%** | -40 ~ -5% | ✅ | 91% |
| 잠정 정방향 | +61.4% | +51.0% | +51.0% | +39.6% | +47.3% | **+50.1%** | +40 ~ +120% | ✅ | 17% |
| 잠정 역방향 | -44.9% | -49.1% | -48.4% | -45.4% | -50.5% | **-47.7%** | 0% 미만 | ✅ | 95% |
| (참고) 초고속 몰빵 | +80.9% | +81.8% | +83.3% | +80.7% | +79.2% | +81.2% | — | | 5% |

- 평균은 8개 전략 모두 목표 안이다. 다만 분위기 전략은 3·4회가 하한(+5%) 근처, 잠정 정방향은 4회가 +39.6%로 데이터에 따라 하한에 걸칠 수 있다 → 단계 B 실제 데이터로 다시 확인.
- 참고 전략 2개는 "사람이라면 가장 큰 호재 1종목에 몰빵하겠지"를 흉내 낸 것이다. 목표는 없지만, 사람이 할 수 있는 가장 빠른 플레이도 +81% 수준임을 확인했다.

### 조정 전(단계 A 끝) → 조정 후

| 전략 | 조정 전 평균 | 조정 후 평균 | 무엇 때문에 |
|---|---|---|---|
| 지연 추종 | -8.6% ❌ | +2.8% ✅ | 즉시 반영: 들고 있던 종목을 다음 뉴스 발표 뒤에 팔게 되어, 분위기에 맞는 다음 뉴스의 즉시 몫을 일부 얻음 |
| 초고속 추종 | +535.6% ❌ | +70.3% ✅ | 즉시 반영 75% (5초 안에 사도 25%만 얻음) |
| 분위기 전략 | +5.7% (2번 미달) | +11.9% ✅ | 분위기 편향 75% |
| 잠정 정방향 | +54.1% | +50.1% ✅ | 즉시 반영으로 내려간 만큼 단서 확률 70%로 보정 |

### 즉시 반영 몫을 고른 과정 (5번 × 100판 평균, 다른 설정은 그때 기준)

| 즉시 몫 | 지연 추종 | 초고속 추종 | 초고속 몰빵(참고) | 잠정 정방향 |
|---|---|---|---|---|
| 0% (이전 규칙) | -8.9% | +536.7% | +888.6% | +59.0% |
| 60% | -2.8% | +113.2% | +147.0% | +42.5% |
| 70% | -2.2% | +76.8% | +97.0% | +38.3% |
| **75% (선택)** | -1.3% | +62.4% | +75.8% | +35.7% |
| 80% | -0.5% | +48.4% | +56.7% | +33.3% |

75%는 초고속 추종이 목표 한가운데 근처이고, 사람형 몰빵도 +80% 안팎에 머무는 값이다. 잠정 정방향이 내려간 만큼은 단서 확률(70%)과 분위기 편향(75%)으로 되찾았다.

| 단서대로 나올 확률 | 정방향 | 역방향 | 차이 |

### 기본 OFF 옵션 (켜지 않는다)

| 옵션 | 지연 추종 | 초고속 추종 | 판단 |
|---|---|---|---|
| 기본 (모두 OFF) | +2.3% | +69.1% | |

### 추첨 조합에 따른 차이
활성 core 테마 수(11~12 / 13~14 / 15+)에 따른 중앙값 차이는 몇 %p 수준이다 (예: 분위기 전략 +12.5% / +9.4% / +15.2%). 조합에 따라 크게 갈리는 구성은 보이지 않았다.

### 남은 주의점
- **판마다 편차가 크다**: 지연 추종 하위 10% -31%, 상위 10% +48%. 실력보다 운이 크게 보일 수 있다 → 실제 기록으로 체감 확인 (`docs/telemetry.md` 4장).
- 시뮬레이션 봇은 사람과 다르다. 실제 플레이 기록으로 다시 맞춰야 한다 → 수집 구조는 `docs/telemetry.md`, 규칙 검토와 결정이 필요한 항목은 `docs/logic_review.md`.
