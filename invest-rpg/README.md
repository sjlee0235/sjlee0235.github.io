# 투자 RPG (가제)

모바일(iOS/Android)용 2D 픽셀 RPG풍 투자 시뮬레이션 게임.
감으로 투자하다 전 재산을 잃은 20대 후반 청년이 공부하고, 인형 눈 붙이기로 모은 1만 비트로 다시 시작하는 이야기.

**현재 단계: W1 — 게임 규칙 엔진** (화면·그림·저장·결제·광고 없음)

---

## 1. 실행 방법

### 준비 (처음 한 번)
1. [Node.js](https://nodejs.org) **22.18 이상** (LTS 버전)을 설치한다.
   - Node.js = 컴퓨터에서 자바스크립트/타입스크립트를 실행해 주는 프로그램
2. 터미널을 열고 이 폴더로 이동한 뒤 필요한 도구를 설치한다.
   ```bash
   cd invest-rpg
   npm install
   ```

### 자주 쓰는 명령

| 명령 | 하는 일 |
|---|---|
| `npm test` | 자동 테스트 전체 실행 (게임 규칙이 맞는지 검사) |
| `npm run demo` | 2000년대 한 시대를 터미널에서 끝까지 돌려 보기 (시드 42) |
| `npm run demo -- 7` | 시드를 7로 바꿔 데모 실행 (같은 시드 = 같은 결과) |
| `npm run typecheck` | 타입 검사 (+ 엔진이 화면 코드 없이 컴파일되는지 검사) |
| `npm run check` | 타입 검사 + 테스트 한 번에 |
| `npm run test:watch` | 파일을 고칠 때마다 테스트 자동 재실행 |

### 화면(W2 이후)에서 엔진을 쓰는 법

```ts
const game = new Game({ eras: ALL_ERAS, seed: 12345 });

// 화면 쪽 타이머가 10초마다 호출. 팝업 중이면 아무 일도 안 일어난다.
setInterval(() => {
  const r = game.advanceTick();
  if (r.advanced && r.news) showNewsPopup(r.news);          // 뉴스 팝업 띄우기
  if (r.advanced && r.settlement) showSettlement(r.settlement); // 시대 정산 화면
}, 10_000);

// 팝업 '확인' 버튼 → 이때 10초 타이머를 새로 시작하면 "확인 후 10초 뒤 반영"이 된다
game.confirmNews();

game.buy('2000s-defense', 3);      // 매수 (자동 즐겨찾기)
game.getStockList();               // 즐겨찾기 우선 정렬된 종목 목록 (가격, 등락, 색)
game.getPortfolio();               // 현금, 총 자산, 종목별 평균가·손익
game.getChart('2000s-defense');    // 최근 20분 가격
game.startNextEra();               // 정산 화면 이후 다음 시대로
```

엔진은 실제 시계를 쓰지 않으므로, 시간 정지·배속·테스트를 화면 쪽에서 자유롭게 조절할 수 있다.

## 3. 데이터 추가 방법

- **새 시대**: `src/data/eras/2010s.json`을 `2000s.json`과 같은 형태로 만들고 `eras/index.ts`의 배열에 한 줄 추가한다.
  진행 순서는 JSON의 `order` 값(예: 2010)으로 정해진다. 1980s(1980)·2030s(2030)도 같은 방식.
- **뉴스 추가**: `newsPool`에 항목을 추가한다. 시대당 24개가 뜨므로 **풀은 24개 이상(권장 40개)** 이어야 한다.
- `npm test`를 실행하면 데이터 검사기가 다음을 확인한다.
  - 테마 20개 (긍정 7 / 부정 7 / 중립 6), 테마당 종목 1개
  - 영향도는 -10~10 정수, 없는 테마를 가리키지 않음
  - 한국어·영어 텍스트가 비어 있지 않음
  - 종목명·뉴스 본문에 실존 기업명이 없음 (간단한 금지어 목록)
- 뉴스의 `source` 필드는 검증용 메모다(게임 화면에 안 나옴). `needsVerification: true`는 "확인 필요"라는 뜻이다.

## 4. 확정된 규칙 (요약)

| 항목 | 값 |
|---|---|
| 1틱 | 게임 시간 10초 |
| 시대 길이 | 720틱 (2시간), 시대 3개: 2000s → 2010s → 2020s |
| 평소 틱 변동 | -3.0% ~ +3.0%, 소수점 1자리 |
| 1분(6틱) 누적 한도 | 변동률 합 ±3% |
| 뉴스 | 30틱(5분)마다 1개, 시대당 24개, 시드 기반 중복 없는 추첨 |
| 뉴스 영향 | 영향도(-10~+10) × 3%, '확인' 후 첫 틱에 한 번에 반영 |
| 가격 | 시대 시작 1,000 비트, 정수, 최소 1 |
| 시작 자금 | 10,000 비트, 시대 종료 시 전량 청산 후 이월 |
| 수수료 | 0 (config.ts의 `feeRate`로 변경 가능) |
| 색상 | 한국식(상승 빨강/하락 파랑) 기본, 서양식(상승 초록/하락 빨강) 옵션 |

## 5. 가정한 규칙 (기획에서 정하지 않아 임의로 정한 것 — 바꾸고 싶으면 알려주세요)

### 시간·뉴스
1. **뉴스 시점은 0, 30, 60, …, 690틱**이다. 시대 시작 직후(0:00:00)에 첫 뉴스가 뜨고, 마지막 뉴스는 1:55:00에 뜬다.
   영향은 '확인' 후 첫 틱(1, 31, …, 691틱)에 반영된다. 이렇게 해야 24개 모두가 시대 안에서 반영된다.
2. 720틱(시대 마지막)이 끝난 뒤에는 뉴스가 뜨지 않고 바로 정산한다.
3. 뉴스 팝업이 떠 있는 동안에는 **매매도 할 수 없다**. 시대가 끝난 뒤에도 매매할 수 없다.
4. 시대가 끝나도 다음 시대로 **자동으로 넘어가지 않는다**. 정산 화면을 보여준 뒤 `startNextEra()`를 호출해야 한다.
5. 뉴스는 시대 안에서 **무작위 순서**로 나온다 (실제 연대순이 아님. 예: 2009년 뉴스 다음에 2001년 뉴스).
6. 뉴스 풀이 24개보다 적으면 풀을 다 쓴 뒤로는 뉴스가 뜨지 않는다 (검사기가 경고를 띄움).

### 주가
7. **1분 윈도우는 고정 구간**이다: 1~6틱, 7~12틱, …. 직전 6틱을 계속 보는 방식(슬라이딩)이 아니다.
   그래서 윈도우 경계에서는 연속 2틱의 합이 최대 ±6%가 될 수 있다 (예: 6틱째 +3%, 7틱째 +3%).
8. 누적 한도는 변동률의 **단순 합**으로 계산한다 (복리 아님).
9. 랜덤 변동은 -3.0~+3.0%(0.1% 간격 61가지)에서 **균등하게** 뽑은 뒤 남은 한도 안으로 자른다(clamp).
   한도를 다 쓰면 그 방향으로는 0.0%만 나와서, 가격이 잠시 멈춘 듯 보일 수 있다.
10. **뉴스를 받은 종목**은 그 틱에 랜덤 변동 없이 정확히 "영향도 × 3%"만 적용된다. 이 변동은 어느 윈도우에도 포함되지 않는다.
    그다음 틱부터 그 종목만의 새 6틱 윈도우가 시작된다. 그래서 그 종목은 다른 종목과 윈도우 경계가 달라진다.
11. 한 뉴스 안에 같은 테마가 두 번 나오면 영향도를 **합산한 뒤 ±10으로 자른다**. 뉴스 두 개가 같은 틱에 겹치는 일은 없다.
12. 가격 = 반올림(이전 가격 × (1 + 변동률)), 0.5는 올림, 최소 1.
    정수 반올림 때문에 실제 가격 변화율이 변동률과 조금 다를 수 있다. 특히 가격이 낮을수록 차이가 크고, 1 비트 종목은 작은 변동으로는 움직이지 않는다.
13. 영향받지 않는 종목의 난수 순서는 뉴스 유무와 관계없이 같다 (종목마다 매 틱 난수를 1개씩 소비).
14. 시드: 시대 id별로 주가용·뉴스용 난수를 따로 만든다. 그래서 시대를 추가·삭제해도 다른 시대의 결과는 바뀌지 않는다.

### 계좌
15. 평균 매수가는 이동평균 방식이다. 일부를 팔아도 평균가는 그대로다.
16. 수수료 = 내림(거래금액 × 수수료율). **매수 수수료는 매입원가에 포함**되어 평균가·손익에 반영된다.
17. **구입 순서 = 처음 산 순서**다. 추가로 사도 순서는 그대로이고, 전량 매도 후 다시 사면 맨 뒤로 간다.
18. 시대 시작 자산 = 이월된 현금이다 (이 시점에는 보유 종목이 없음).
19. 정산의 종목별 손익은 **이번 시대에 거래한 모든 종목**(중간에 판 종목 포함)이 대상이다.
    손익률 = 손익 ÷ 이번 시대에 그 종목을 산 총 금액.

### 목록·차트·색상
20. 매수하면 즐겨찾기 **그룹 맨 위**에 자동 추가된다. 이미 즐겨찾기인 종목은 위치를 유지한다. 매도해도 즐겨찾기는 해제되지 않는다.
21. 시대가 바뀌면 종목이 바뀌므로 즐겨찾기는 초기화된다.
22. 목록 색상은 **시대 시작가(1,000) 대비** 등락으로 정한다 (직전 틱 대비 아님). 직전 틱 변동률도 `lastTickPct`로 함께 제공한다.
23. 차트 이력은 최근 **가격 120개**다 (시작가 포함). 120틱이 지나기 전에는 0틱부터 있는 만큼만 돌려준다.

## 6. 검토가 필요한 점

- **밸런스 문제 (중요)**: 지금 규칙에서는 뉴스를 확인한 뒤, 영향이 반영되기 전 10초 안에 매수할 수 있다.
  영향 크기도 정해져 있어서 "호재 종목을 바로 산다"는 단순한 전략만으로 한 시대에 큰 수익이 난다
  (`npm run demo` 기준 시드 42에서 +447%). 해결 방법 후보:
  (a) 실제 반영량에 무작위 폭 추가 (예: 영향도 ±30%)
  (b) 일부 뉴스는 이미 가격에 반영됐거나 반대로 움직임 ("소문에 사서 뉴스에 판다")
  (c) 확인 직후 바로 반영해서 선점 불가
  (d) 이 구조를 의도된 "공부하면 이긴다" 설계로 유지
- 2000년대 테마 분류 중 **건설(부정)**, **금(중립)**은 재검토가 필요하다 (`2000s.json`의 `memo` 참고).
- 2000년대 뉴스는 12개뿐이라 시대당 24개를 채우지 못한다. 출시 전 40개 정도로 늘려야 한다.
- 2000년대 뉴스에 반도체·휴대폰·온라인게임 테마의 **전용 호재 뉴스가 아직 없다**.

## 7. 기술 스택

- TypeScript 7 + Vite 8 + Vitest 5 (추가 라이브러리 없음)
- 화면(Phaser), 앱 포장(Capacitor)은 이후 단계에서 추가
- `scripts/demo.ts`는 Node.js의 타입스크립트 직접 실행 기능을 쓴다 (Node 22.18+).
