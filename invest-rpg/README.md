# 투자 RPG (가제)

모바일(iOS/Android)용 2D 픽셀 RPG풍 투자 시뮬레이션 게임.
감으로 투자하다 전 재산을 잃은 20대 후반 청년이 공부하고, 인형 눈 붙이기로 모은 1만 비트로 다시 시작하는 이야기.
교육용으로도 쓸 수 있도록 **연습 모드**와 **실전 모드**를 둔다.

**현재 단계: W1 — 게임 규칙 엔진** (화면·그림·결제·광고 SDK·서버 없음)

---

## 1. 실행 방법

### 준비 (처음 한 번)
1. [Node.js](https://nodejs.org) **22.18 이상** (LTS 버전)을 설치한다.
   - Node.js = 컴퓨터에서 자바스크립트/타입스크립트를 실행해 주는 프로그램
2. 터미널에서 이 폴더로 이동해 도구를 설치한다.
   ```bash
   cd invest-rpg
   npm install
   ```

### 자주 쓰는 명령

| 명령 | 하는 일 |
|---|---|
| `npm test` | 자동 테스트 전체 실행 (게임 규칙이 맞는지 검사) |
| `npm run sim` | 밸런스 시뮬레이션 (전략 4개 × 모드 2개 × 시드 200개, 약 10초) |
| `npm run sim -- 50` | 시드 50개로 빠르게 |
| `npm run demo -- practice` | 연습 모드 한 판(30분)을 터미널에서 보기 (뉴스마다 관련 테마·해설) |
| `npm run demo -- real 7` | 실전 모드, 시드 7 (같은 시드 = 같은 결과) |
| `npm run typecheck` | 타입 검사 (+ 엔진이 화면 코드 없이 컴파일되는지) |
| `npm run check` | 타입 검사 + 테스트 한 번에 |

### 화면(W2 이후)에서 엔진을 쓰는 법

```ts
// 연습: 시대를 골라 30분 한 판 / 실전: 2000s부터 순서대로
const practice = new Game({ eras: ALL_ERAS, seed, mode: 'practice', eraId: '2000s' });
const real = new Game({ eras: ALL_ERAS, seed, mode: 'real' });

// 화면 쪽 타이머가 5초마다 호출. 일시정지·연습 팝업 중이면 아무 일도 안 일어난다.
const r = game.advanceTick();
if (r.advanced && r.news) {
  const popup = game.getNewsPopup(r.news); // 본문, 관련 테마(긍정/부정), 해설, isHistorical(가상 시나리오 여부)
}
if (r.advanced && r.settlement) showSettlement(r.settlement);

game.confirmNews();               // 연습 팝업 '확인' → 10초(2틱) 뒤 반영
game.suspend(); game.resume();    // 앱이 백그라운드로 갈 때 (틱·뉴스 타이머 모두 정지)
game.getNewsArchive();            // 뉴스 보관함 (태그 direct/indirect/hint/outcome/market)

// 연습 모드 광고 보상 (실전 게임에서는 타입 오류로 호출 자체가 막힘)
await practice.watchAdForReward(new MockAdRewardService()); // 끝까지 보면 +3,000 비트, 판당 3회
practice.startPracticeRound('2000s');                       // 새 판: 10,000 비트로 리셋
real.startNextEra();                                        // 실전: 다음 시대 (자금 이월)
```

## 3. 데이터 작성 방법

### 뉴스
```jsonc
{
  "id": "2000s-n19-oil-147",
  "category": "market",              // 시장 전체 뉴스(금리·전쟁·유가·환율). 기본은 "theme"
  "title": { "ko": "...", "en": "..." },
  "body":  { "ko": "...", "en": "..." },
  "effects": [
    { "themeId": "refining", "impact": 7,  "link": "direct" },
    { "themeId": "travel",   "impact": -3, "link": "indirect",
      "explanation": { "ko": "유가↑ → 항공권↑ → 여행↓", "en": "..." } }   // 테마별 한 줄 해설 (선택)
  ],
  "explanation": { "ko": "3~4문장 해설", "en": "..." },  // 영향이 모두 direct면 필수 (연습 모드에 나옴)
  "reactionNote": { "ko": "반대 반응 이유", "en": "..." }, // 결과 뉴스가 예상과 반대로 움직일 때 (선택)
  "source": { "event": "서술형 사건명(실명 금지)", "date": "2008-07-11", "impactRationale": "근거", "needsVerification": false }
}
```
- `link`: `direct`(1차 영향: 기사만 읽어도 앎) / `indirect`(2차 영향: 한 번 더 생각해야 함)
- **영향이 모두 `direct`인 뉴스만 연습 모드에 나온다.** 이런 뉴스는 해설이 필수다 (한/영, 3~4문장, 중학생 눈높이, 투자 권유 금지).
- 시장 전체 뉴스도 모든 종목에 같은 방향이 아니라 **테마별로 다르게** 쓴다 (예: 금리 인상 → 건설 -, 카드 -, 증권 -).

### 스토리 (낌새 → 단서 → 결과, 실전 전용)
```jsonc
{
  "id": "2000s-story-nk-nuclear",
  "signal": { /* 낌새 뉴스, 영향도 1~3. 본문에 판단 근거를 넣는다 */ },
  "news": [ /* 결과·단서 뉴스들 */ ],
  "outcomes": [
    { "newsId": "2000s-s2-nk-test",  "isHistorical": true },    // 기본 가중치 70%
    { "newsId": "2000s-s2-nk-talks", "isHistorical": false }    // 가상 시나리오, 30%
  ],
  "clues": [ { "newsId": "...", "pointsTo": "결과 newsId" } ]   // 선택
}
```

### 검사 (`npm test` 때 자동)
- 테마 20개(7/7/6), 테마당 종목 1개
- 영향도 -10~10 정수(0 금지), 뉴스당 직접 영향 테마 최대 8개
- 연습용 뉴스 해설 3~4문장
- 낌새 영향도 1~3, 결과는 낌새보다 크게, 실제 역사 쪽 결과 필수
- 영향도 분포 1~3 / 4~6 / 7~10 = 40 / 40 / 20% (±10%)
- 공급량: 실전 36자리 이상, 연습 직접 뉴스 14개 이상
- 앱에 들어가는 JSON 전체(근거 메모 포함)에 실존 기업명·인물명 금지 (실명은 `docs/` 팩트체크 문서에만)

## 4. 확정된 규칙

| 항목 | 값 |
|---|---|
| 상수 | `TICK_SECONDS=5`, `MAX_TICK_MOVE=1.5`, `WINDOW_TICKS=12`, `WINDOW_CAP=3.0` (나머지는 여기서 계산) |
| 시간 | 실전 시대당 2시간(1,440틱), 연습 한 판 30분(360틱), 차트 20분(240개) |
| 평소 틱 변동 | -1.5% ~ +1.5%, 소수점 1자리 |
| 1분 누적 한도 | 변동률 합 ±3%. 넘으려 하면 **반대로 튕겨냄(반사)** |
| 뉴스 시점 | 첫 뉴스 1~3분, 이후 3~6분 간격 무작위 (같은 뉴스 반복 없음, 풀이 바닥나면 더 안 나옴) |
| 뉴스 영향 | 영향도(-10~+10) × 3% × **배율**, 10초 뒤 한 번에 반영 (최대 ±30%) |
| 배율 | 실전 직접 0.6~1.4 / 실전 간접 0.4~1.6 / 연습 0.85~1.15 (균등분포, 영향마다 따로 뽑음) |
| 뉴스 후 관성 | 20초(4틱): 유지 60% / 반대 20% / 정지 20%, 크기 0.1~0.5%, 1분 한도 제외 |
| 스토리 | 실전만. 결과는 낌새 후 15분 안의 뉴스 자리, 동시 1개, 종료 15분 전부터 새 낌새 없음, 실제 역사 70% |
| 연습 모드 | 직접 뉴스만, 스토리 없음, 팝업 중 시간 정지, 매 판 10,000 비트, 시대 선택, 이월 없음 |
| 광고 보상 | 연습만, 1회 3,000 비트, 판당 3회 (실전 없음) |
| 수수료 | 매수·매도 각 0.2% (연습·실전 동일) |
| **수익률** | **(최종 자산 − 시작 자금 − 누적 광고 보상) ÷ (시작 자금 + 누적 광고 보상) × 100** |

## 5. 가정한 규칙 (바꾸고 싶으면 알려주세요)

표시: 🆕 이번에 새로 정함 · ✏️ 이번에 바뀜 · (표시 없음) 전과 같음

### 뉴스 일정
1. 첫 뉴스는 시작 후 1~3분 사이에 뜬다. 마지막 뉴스는 반영(10초)과 관성(20초)이 끝나는 시점까지만 뜬다.
2. 일정은 판 시작 때 시드로 한꺼번에 정한다. 단독 뉴스와 스토리를 섞어 무작위로 배치한다.
3. ✏️ 연습 모드는 **영향이 모두 직접인 단독 뉴스만** 나온다. 섞인 뉴스에서 직접 영향만 골라 쓰던 방식은 없앴다.
4. 🆕 스토리 결과는 낌새 이후 15분 안에 오는 **빈 뉴스 자리 중 하나**를 무작위로 차지한다. 그래서 3~6분 간격은 그대로 유지된다. 15분 안에 빈자리가 없으면(시대 끝 무렵) 그 스토리는 이번 판에서 건너뛴다.
5. 🆕 결과가 나오기 전에는 다른 스토리의 낌새가 시작되지 않는다 (동시 1개).
6. 🆕 단서는 **실제로 뽑힌 결과를 가리키는 것만** 나온다(정직한 단서). 낌새와 결과 사이 빈자리에 들어간다.
7. 🆕 결과에 `weight`가 없으면 실제 역사 쪽이 70%, 나머지가 30%를 나눠 갖는다.
8. 🆕 가상 결과를 가리키는 단서도 `isHistorical: false`로 표시한다 (가상 시나리오의 일부라서).
9. 뉴스 순서는 실제 연대순이 아니다.

### 주가
10. ✏️ 1분 윈도우는 고정 구간(1~12틱, 13~24틱, …)이다. 한도를 넘으면 반사한다. 반사해도 범위를 벗어나는 드문 경우에만 자른다.
11. 🆕 반사 예: 남은 한도 +0.5%에서 +1.2%가 나오면 0.5 − 0.7 = **-0.2%**가 된다.
12. ✏️ 뉴스 반영 틱에서 윈도우를 리셋한다. 관성 4틱은 윈도우에서 제외하고, 관성이 끝날 때 다시 리셋한다.
13. 🆕 배율은 영향 하나하나마다 따로 뽑는다. "market" 영향은 테마마다 따로 뽑는다. 합산한 뒤 0.1% 단위로 반올림하고 ±30%로 자른다.
14. 🆕 관성 크기는 0.1~0.5%다. 밸런스 조정 4단계 결과이며, 설정값 `momentumRate`로 바꿀 수 있다.
15. 가격 = 반올림(이전 가격 × (1 + 변동률)), 0.5 올림, 최소 1.
16. ✏️ 시드는 시대 id(연습은 + 판 번호)별로 주가·뉴스 일정·배율 난수를 따로 만든다.

### 계좌·지갑
17. 🆕 연습 지갑과 실전 지갑은 별개다. 연습 판이 끝나도 실전 자금에는 영향이 없다.
18. 🆕 연습 모드는 매 판 10,000 비트로 시작하고 시대를 골라 플레이한다. 시대 간 이월은 없다. (`startPracticeRound`)
19. 🆕 광고 보상은 판 중 언제든(정산 화면 포함) 받을 수 있다. 광고를 끝까지 보지 않으면 지급하지 않는다. 횟수가 남지 않았으면 광고를 띄우지 않는다.
20. ✏️ 수수료는 내림(거래금액 × 0.2%)이고, 매수 수수료는 매입원가에 포함한다.
21. 🆕 연습 팝업이 떠 있거나 일시정지 중일 때는 매매할 수 없다.
22. 평균가는 이동평균, 구입 순서 = 처음 산 순서, 매수 시 즐겨찾기 자동 추가.

## 6. 밸런스 시뮬레이션 결과 (시드 200개, 2000년대)

### 전략별 시대당 수익률

| 모드 | 전략 | 중앙값 | 하위 10% | 상위 10% | 목표 | 결과 |
|---|---|---|---|---|---|---|
| 실전 | 무작위 매매 | -0.7% | -14.7% | +12.4% | -10% ~ +5% | ✅ |
| 실전 | 균등 매수 후 보유 | +8.1% | -2.3% | +17.9% | -10% ~ +20% | ✅ |
| 실전 | **즉시 추종** | **+939.8%** | +671.7% | +1380.6% | +30% ~ +60% | ❌ |
| 실전 | 학습형 | +776.6% | +554.0% | +1156.0% | 추종보다 높게, +150% 미만 | ❌ |
| 연습 | 무작위 매매 | +0.1% | -6.8% | +7.9% | -10% ~ +5% | ✅ |
| 연습 | 균등 매수 후 보유 | +2.5% | -2.3% | +9.2% | -10% ~ +20% | ✅ |
| 연습 | 즉시 추종 | +99.0% | +70.2% | +137.0% | +60% ~ +100% | ✅ (상한 근처) |

평소 틱 중 0.0% 비율: **3.8%** (목표 5% 이하 ✅, 이전 15%)

### 조정 수단을 하나씩 적용한 효과 (즉시 추종 중앙값)

| 단계 | 실전 2시간 | 연습 30분 |
|---|---|---|
| 0) 기준 (분포 적용 전, 배율 없음, 수수료 0, 관성 0.1~1.5%) | +1003.7% | +96.9% |
| 1) + 반영 배율 무작위 | +962.3% | +96.8% |
| 2) + 영향도 분포 40/40/20 (강한 영향 비율 11% → 20%) | +1233.6% | +114.6% |
| 3) + 수수료 0.2% | +1126.3% | +107.4% |
| 4) + 관성 크기 0.1~0.5% (현재 기본값) | +939.8% | +99.0% |

(2단계는 강한 영향의 비율이 늘어나서 오히려 수익이 커졌다.)

### 왜 실전 즉시 추종이 목표에 못 닿는가
- 뉴스가 뜬 뒤 **반영까지 10초 동안 매수할 수 있어서**, 뉴스를 보고 바로 사면 그 뉴스의 움직임을 거의 다 얻는다.
- 그래서 뉴스당 기대 이익 ≈ 평균 영향도 × 3%이고, 배율은 평균이 1이라 이 값을 줄이지 못한다. 실전 한 시대에 뉴스가 약 27개라서 복리로 쌓이면 +900% 이상이 된다.
- 학습형도 같은 이유로 즉시 추종을 넘을 수 없다. 결과 뉴스의 움직임은 즉시 추종도 반영 전에 다 얻기 때문에, 미리 걸어 두는 이점이 없다.

### 선택지 (규칙을 바꾸는 것이라 결정이 필요함)

| 선택지 | 내용 | 실전 즉시 추종 중앙값 (측정) |
|---|---|---|
| A | 실전: 뉴스가 뜬 뒤 반영까지 10초 동안 **해당 종목 매수 잠금** (또는 주문은 반영 후 가격으로 체결) | +14.6% |
| A' | A + 관성 크기 0.1~1.5%로 복구 | +29.4% |
| B | 뉴스 전 1~2분 동안 영향 일부가 **미리 움직임**(소문 선반영) | 미측정 (엔진 변경 필요) |
| C | 실전 배율에 반대 반응 포함 (예: 직접 -1.0~1.4) | +36.5% (뉴스 신뢰도가 크게 떨어짐) |
| D | 현재 유지: 실전은 "읽고 빨리 판단하면 크게 이긴다"는 설계로 받아들임 | +939.8% |

추천은 **A'**: 10초 반영 규칙과 영향도 규칙은 그대로 두고 선점만 막는 방식이다.
이 경우 즉시 추종은 +29%대가 되고, 학습형(낌새로 미리 거는 전략)이 의미를 갖게 된다.
