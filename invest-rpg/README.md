# 투자 RPG (가제)

모바일(iOS/Android)용 2D 픽셀 투자 시뮬레이션 게임. 하단 탭 4개(거실 / 주식창 / 작업실 / TV홈쇼핑)의 1인칭 화면으로 진행한다 (걷는 맵·캐릭터 없음).
감으로 투자하다 전 재산을 잃은 20대 후반 청년이 공부하고, 인형 눈 붙이기로 모은 1만 코인으로 다시 시작하는 이야기.

**현재 단계: 도트 시안 적용 — 직접 플레이할 수 있는 시험판** (결제·광고·서버 없음)
- **이번(5차)**: 받은 도트 시안(`docs/DESIGN_HANDOFF.md`, 그림 PNG)대로 화면 전체를 다시 만듦 — 밤/낮, 인테리어 0~7단계(단계당 2,000코인, 시대 이월), 돌아다니는 강아지와 터치 반응, 주식창 바로 체결, 인형 100개 묶음 지급, 처음 안내·기록 동의 창. **웹 시험판**은 아래 "웹에서 해 보기"
- 기본으로는 **2000년대 한 시대**만 플레이한다 (2010·2020년대 콘텐츠는 아직 없음)
- 단계 A(엔진·스키마·테스트·시뮬레이션·점검 스크립트) 완료 → 2차 결정(공개용 뷰, 시간가중수익률, 세이브 보강) 반영
- 3차 기획 변경 반영: 화폐 코인, 시대 시작 7분 유예와 opener 첫 뉴스, 종목명 "수식어 업종주", 일시정지 사유·뉴스 피드·주가 리포트 행·1배/2배속, 작업(인형 눈 붙이기)과 시대 종료 지급, 거실(LP 음악·강아지), 시대별 디자인 데이터, 탭 레지스트리
- **단계 U(이번)**: 브라우저에서 도는 화면 — 4탭(거실·주식창·작업실·TV홈쇼핑), HTS 주식창, 정산 창, 설정, 디버그 패널, 픽셀 아트(코드로 그림), 스크린샷 스크립트
- **단계 B 초안(이번)**: 2000년대 데이터 `src/data/eras/2000s.json` — 테마·종목 36개, 속보 23개, 스토리 12개(opener 6개). 기획자 검토 전 초안 (`docs/stageB_candidates.md` 4장, 팩트체크 `docs/2000s_fact_check.md`)
- 2010년대·2020년대는 아직 없다. 화면은 이 두 시대를 **가상 시대**로 채운다 (화면 왼쪽 아래 `VIRTUAL DATA` 표시). `sim:repeat`·`sim:carry`는 계속 가상 시대로 규칙을 점검한다.
- 화면 단계 인계: `docs/ui_handoff.md`, 화면 구성: `docs/screens.md`, 경제: `docs/economy.md`

## 1. 실행 방법

1. [Node.js](https://nodejs.org) **22.18 이상** 설치 (Node.js = 컴퓨터에서 타입스크립트를 실행해 주는 프로그램)
2. `cd invest-rpg && npm install`

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | **화면 켜기** (아래 "화면 보는 법") |
| `npm run shots` | 화면 스크린샷 14장 (시안과 같은 390×844, 밤·낮, 작은 화면 1장) → `shots/` 폴더 |
| `npm run e2e` | 브라우저 흐름 점검 49개: 처음 안내·동의, 앱 업데이트 정산 뒤 다음 시대, 끝난 판 다시 열기, 숨긴 탭 일시정지, 매매(최대·바로 체결·즐겨찾기), NEWS!, 인테리어, 인형 100개 지급, 강아지, 밤/낮 |
| `npm run build` | 운영용 파일 만들기 → `dist/` (디버그 패널은 빠진다). `npm run preview`로 확인 |
| `npm run build:play` | **웹 시험판** 만들기 → `play/` 폴더 (주소 끝에 `#debug` 또는 `?debug=1`을 붙이면 디버그 패널) |
| `npm test` | 자동 테스트 전체 |
| `npm run check` | 타입 검사 + 테스트 |
| `npm run sim` | 밸런스 시뮬레이션 (전략 10개 + 참고 2개 × 시드 200개). `npm run sim -- 50`으로 빠르게 |
| `npm run sim:repeat` | 반복 시뮬레이션: 서로 다른 가상 데이터·시드로 5번 × 200판, 평균·손실 확률·뉴스 구성·목표 판정 (약 3분) |
| `npm run sim:carry` | 3시대 연속 이월 시뮬레이션: 전략별 최종 자산 분포, 자산이 1,000코인 아래로 떨어진 비율 |
| `npm run lint:content` | 콘텐츠 작성 가이드 점검 (영향 테마 수, 영향도 공식, opener 3개, 종목명·설명, 금지어 등) |
| `npm run lint:audio` | 음악 라이선스·파일 점검. 출시 전 `npm run lint:audio -- --release` (임시 곡이 있으면 실패) |
| `npm run audio:placeholder` | 장르당 2곡, 1초 무음 임시 곡 만들기 (재생 흐름 시험용) |
| `npm run telemetry:report` | 플레이 기록 분석 리포트 (봇 기록으로 점검, 또는 `-- 기록.jsonl`) |
| `npm run demo` | 한 시대를 터미널에서 끝까지 (뉴스·주가 리포트 출력). `npm run demo -- 7`은 시드 7 |
| `npm run demo -- tutorial` | 튜토리얼 흐름 |

### 화면 보는 법 (휴대폰 크기로)

1. 터미널에서 `cd invest-rpg` → `npm run dev`
2. 터미널에 나온 주소(보통 `http://localhost:5173/`)를 크롬에서 연다
3. 휴대폰 크기로 보기: 크롬에서 `F12`(개발자 도구) → 왼쪽 위 휴대폰 모양 아이콘(기기 툴바) → 위쪽 크기 칸에 `360 × 640` 또는 `390 × 844` 입력
4. **같은 와이파이의 휴대폰**에서 보려면 터미널에 나온 `Network:` 주소(예: `http://192.168.0.5:5173/`)를 휴대폰 브라우저에서 연다
5. 끄기: 터미널에서 `Ctrl + C`

시간 건너뛰기(개발 서버·웹 시험판): 주소 뒤에 `?debug=1`(또는 `#debug`)을 붙이면 오른쪽 아래에 `DEBUG` 버튼이 뜬다. 누르면 패널이 열린다.

| 버튼·주소 | 하는 일 |
|---|---|
| `시간 ×10 켜기/끄기` | 시간 10배 빠르게 (다시 누르면 보통) |
| `다음 뉴스까지` | 다음 뉴스가 나올 때까지 건너뛰기 |
| `+5분` / `시대 끝내기` | 게임 시간 5분 진행 / 시대 끝까지 (정산 창) |
| `+1000코인` | 코인 지급 (입금으로 처리되어 수익률에는 안 잡힘) |
| `인형 터치 ×30` | 인형 10개 완성 (100개 지급 확인용) |
| `인테리어 +1단계` | 모자라는 코인을 채워 주고 한 단계 올림 |
| `밤/낮 바꾸기` | 현지 시각과 상관없이 밤 ↔ 낮 |
| `seed` · `era` · `새 게임` | 시드 고정·시작 시대를 골라 새 게임 (주소: `?debug=1&seed=7&era=1&fresh=1`). `&virtual=1`이면 가상 2010·2020년대까지 3시대, `&nointro=1`이면 처음 안내 건너뜀 |

### 웹에서 해 보기 (시험판)

- `npm run build:play`로 만든 `play/` 폴더가 그대로 웹 게임이다 (그림·코드 모두 상대 주소).
- 이 저장소는 GitHub Pages(`https://sjlee0235.github.io/`)이므로 이 브랜치를 `main`에 합치면 **`https://sjlee0235.github.io/invest-rpg/play/`** 에서 열린다. (합치기 전에는 Claude가 만들어 준 비공개 미리보기 링크로 해 볼 수 있다.)
- 휴대폰 브라우저에서 열면 화면 크기에 맞춰 390×844 무대를 통째로 키우거나 줄인다. 진행은 그 브라우저에 자동 저장된다.

저장: 진행 상황은 브라우저에 자동 저장된다. 처음부터 다시 하려면 `?debug=1&fresh=1`로 열거나 브라우저의 사이트 데이터를 지운다.

### 화면(W2 이후)에서 엔진을 쓰는 법

화면은 **공개용 뷰 `PublicGame`만** 쓴다 (`docs/ui_handoff.md`). 엔진 본체 `Game`은 뉴스의 영향 방향·테마 분위기 같은 숨김 정보를 들고 있다.

```ts
const game = PublicGame.create({ eras: ALL_ERAS, seed, locale: 'ko' });  // 시대 시작 때 테마 20개 추첨
const tabs = new TabController(game);                                    // 시대 시작 탭 = 주식창

// 화면 타이머: tickIntervalMs(game.getSpeed())마다 (1배 5초, 2배 2.5초). 뉴스·리포트로 시간이 멈추지 않는다
const r = game.advanceTick();
if (r.advanced) { updatePrices(r.prices); tabs.onTick(); }
if (r.advanced && r.news) refreshFeed(game.getFeed());       // 피드: 최신순 [{ news, report?, unread }]
if (r.advanced && r.reports.length) refreshFeed(game.getFeed()); // 발표 120초 뒤 그 뉴스 아래에 주가 리포트 행
```

## 3. 데이터 구조

### 테마 (시대마다 풀 36개, 테마당 종목 1개)
```jsonc
{ "id": "semiconductor", "name": {"ko": "...", "en": "..."},
  "sentiment": "positive",        // positive 13 / negative 13 / neutral 10 (플레이 중 숨김)
  "relevance": "core",            // core 24 : peripheral 12 (분위기와 독립, 플레이 중 숨김)
  "keywords": { "ko": ["반도체", "메모리", ...], "en": [...] },   // 5~8개
  "existsEvidence": "그 시대에 존재했다는 근거 한 줄 (모르면 '확인 필요')" }
```
- 비주류(peripheral) 테마는 주로 시장 전체 뉴스·간접 영향으로 움직이는 '배경 종목'이다. 뉴스 풀 전체에서 최소 2회는 영향 대상이어야 한다.

### 종목 (테마당 1개, 가상 회사)
- 한국어 이름은 **"수식어 업종주"** — 반드시 **'주'로 끝난다** (예: `평화 방산주`, `온유 제약주`). 수식어는 2글자의 테마 관련 명사·형용사.
- 영어 이름은 **`Stock`으로 끝난다** (예: `Peace Defense Stock`).
- 평가·전망 어감(최강, 폭등, 유망, 위기, 호황, 불황 등)은 금지. "평화"처럼 뉴스 방향을 간접적으로 암시할 수 있는 단어는 막지 않고 **경고**만 (목록 `STOCK_NAME_HINT_WORDS`).
- 기업 설명은 **1~2줄(한국어 80자 안팎)**, 제품·서비스 중심의 중립 서술. 전망·평가 표현 금지.
- 실존 기업명·상표·인물명 금지. 모두 `lint:content`와 테스트가 검사한다.

### 뉴스
```jsonc
{ "id": "...", "type": "breaking",   // breaking(속보) / tentative(잠정) / outcome(결과)
  "magnitude": 7,                     // 뉴스 규모: 속보 3~9, 잠정 1~3, 결과 7~9 위주
  "title": {...}, "body": {...},      // 본문에 연도·월 표기 금지
  "effects": [{
    "themeId": "refining", "impact": 7,
    "link": { "strength": 3,          // 3 직접 / 2 밀접 / 1 간접
              "keywords": [{ "newsTerm": "유가", "themeTerm": "정유" }],
              "chain": "강도 2·1일 때 연결 설명" },
    "reason": { "ko": "주가 리포트용 한 줄 이유" },   // 영향도 절댓값 상위 4개는 한국어 필수
    "adjustNote": "공식에서 ±1 조정했을 때 이유" }],
  "realDate": "2008-07-11",           // 근거 확인용 메타데이터
  "reactionNote": {...} }             // 결과 뉴스가 반대로 반응할 때 (실제 기록 근거가 있을 때만)
```
- **영향도 공식**: `|impact| = max(1, round(magnitude × 계수))`. 계수는 강도 3 → 1.0, 2 → 0.6, 1 → 0.3이고, 부호는 호재/악재다.
- 제목·본문에 **주가 방향을 직접 알려주는 표현 금지**: 호재, 악재, 수혜, 수혜주, 타격주, 상승 예상, 하락 예상. 사건 자체의 표현("유가 급등")은 괜찮다.
- 영향 테마 6~9개. 호재와 악재를 섞는다. 분위기 편향(긍정 테마 호재 약 **75%**, 부정 테마 악재 약 75%, 중립 50%)을 맞춘다.

### 스토리 (잠정 → 결과)
```jsonc
{ "id": "...", "tentative": { /* 잠정 뉴스 */ },
  "news": [ /* 결과 2개 (+ 단서) */ ],
  "outcomes": [ { "newsId": "A", "isHistorical": true }, { "newsId": "B", "isHistorical": false } ],
  "leansTo": "A",                    // 잠정 뉴스 본문의 단서가 가리키는 결과 = 실제 역사 (B5)
  "clues": [ { "newsId": "...", "pointsTo": "A" } ],   // 선택
  "opener": true }                   // 시대 첫 뉴스 후보 (단서가 읽기 쉽고 사건이 직관적인 것)
```
- 결과는 **항상 서로 반대인 2개**다 (공통 테마의 부호가 반대). 검사기가 확인한다.
- 결과는 그때그때 추첨한다. 단서(`leansTo`)대로 **65%**, 반대로 35%다 (`LEAN_PROB`).
- **단서 쪽 결과는 실제 역사**(`isHistorical: true`)로 맞춘다 (B5, `lint:content`가 검사).
- **opener 스토리는 시대당 3개 이상** (`lint:content`가 검사). 시대 첫 뉴스(7분)는 사용 가능한 opener 중에서 시드 기반 무작위로 고른다.

## 5. 가정한 규칙 (바꾸고 싶으면 알려주세요)

표시: 🆕 이번(3차)에 새로 정함 · ✏️ 이번에 바뀜 · ⚠️ 확정 규칙을 바꾼 것 (기획자 결정·승인) · (표시 없음) 전과 같음

### 확정 규칙 변경 기록
- ⚠️ **뉴스 반영 시점** — 기존: 발표 5초 뒤 100% 반영 → 변경: **발표 즉시 75% + 5초 뒤 25%** (`INSTANT_REACTION_SHARE = 0.75`). 이유: 기존 규칙에서는 뉴스를 보고 5초 안에 사면 영향 전부를 공짜로 얻어, 초고속 추종 전략이 시대당 **+536%**(몰빵 +889%)였다. 기획자 승인.
- ⚠️ **잠정 뉴스 단서 확률** — 60% → 65% → 70% → **65%**(기획 결정, `LEAN_PROB`). 한 판에 같은 스토리는 한 번뿐이라 확신보다 분산 투자를 고르게 한다. 잠정 정방향 목표 +25~100%.
- ⚠️ **수익률 공식** — 단순 수익률 → **시대별 시간가중수익률**. 입금이 수익으로 잡히지 않게.
- ⚠️ 🆕 **첫 뉴스** — 기존: 시대 시작 후 1~3분 → 변경: **처음 7분은 뉴스 없음, 첫 뉴스는 정확히 7분의 opener 잠정 뉴스** (3차 기획).
- ⚠️ 🆕 **화폐 이름** — 비트 → **코인** (3차 기획). 바꾼 줄 목록은 `docs/rename_bit_to_coin.md`.
- ⚠️ 🆕 **종목명** — "2글자 수식어 + 업종"('주' 금지) → **"수식어 업종주"('주'로 끝남), 영어 "... Stock"**, 설명 3줄 내외 → **1~2줄(80자 안팎)** (3차 기획).
- ⚠️ 🆕 **주가 리포트(이전 이름: 해설 알림)** — 뉴스 피드의 그 뉴스 아래에 붙는 행. 팝업 아님, 시간을 멈추지 않음 (3차 기획).
- ⚠️ 🆕 **작업 수입** — 즉시 입금 → **시대 종료 때 합산 지급** (3차 기획). `WORK_PAYOUT_MODE='immediate'`로 되돌릴 수 있다.

### 시대 시작·추첨
1. 분위기 그룹마다 따로 섞어서 앞에서부터 뽑는다(층화 추첨). 재추첨 시드는 원래 시드에서 시도 번호로 만든다.
2. 50회 안에 조건을 못 맞추면 "core 조건 → 속보·스토리·opener 충족 정도" 순으로 가장 나은 추첨을 쓰고, `draw.warning`에 경고를 남긴다.
3. 스토리는 잠정 뉴스와 결과 2개가 모두 유효(유효 영향 테마 3개 이상)해야 쓴다. 유효하지 않은 **단서** 뉴스는 빼고 스토리는 그대로 쓴다.
4. 이번 판에서 뉴스의 영향은 활성 테마 것만 남긴다 (플레이 중에는 보이지 않고, 시대 종료 후 공개에서만).
5. 🆕 첫 슬롯(7분)은 사용 가능한 opener 스토리 중 시드 기반 무작위. opener가 하나도 없으면(추첨 경고 상태) 아무 스토리, 스토리도 없으면 일반 규칙으로 채운다.
6. 🆕 7분 유예와 첫 잠정 뉴스는 **모든 시대**에 적용된다. 튜토리얼은 시대가 아니라서 적용하지 않는다(뉴스 30초 고정).

### 뉴스 일정
7. 빈 슬롯마다(첫 슬롯 제외) 진행 중인 스토리가 없으면 85% 확률로 새 잠정 뉴스, 아니면 속보. 슬롯 기준 속보·잠정·결과가 각각 약 33%.
8. 속보가 바닥나면 스토리를, 스토리가 바닥나면 속보를 넣는다. 둘 다 없으면 그 슬롯은 비운다(반복 없음).
9. 단서 뉴스는 실제로 뽑힌 결과를 가리키는 것만, 잠정과 결과 사이 빈 슬롯에 나온다. 화면에서 단서 뉴스의 종류는 "잠정"으로 표시한다.
10. "가상 시나리오" 태그는 결과 뉴스에만, 발표된 뒤에 붙는다.
11. 마지막 뉴스는 반영·관성이 시대 안에서 끝나는 시점까지만 뜬다.

### 가격
12. 뉴스 사이 한도의 기준가(P0)는 뉴스가 발표되면 모든 종목에서 그 순간 가격으로 다시 잡힌다. 첫 뉴스 전(7분 유예)에는 시대 시작가 1,000.
13. 한도 계산은 정수 가격 기준(하한 올림, 상한 내림). 일반 변동은 1분 한도와 뉴스 사이 한도를 둘 다 만족하도록 반사한다.
14. 뉴스 반영이 한도에 막혀 0%가 되어도, 관성 방향은 원래 반영 방향을 따른다. 관성 크기 0.1~1.5%, 1분 한도에서 제외.
15. 발표 즉시 몫: 종목별 반영률을 0.1% 단위로 75%(0 쪽으로 버림)와 나머지로 나눈다. 나머지가 0이면 최소 ±0.1%는 5초 뒤 몫으로 남긴다.

### 뉴스 피드·주가 리포트
16. ✏️ 주가 리포트(`StockReport`, 이전 `RecapNotice`)의 종목은 활성 종목 중 그 뉴스로 실제 반영이 일어난 종목, 반영률 절댓값 상위 3개 + 나머지 개수. `appliedPct` = `instantPct` + `delayedPct`(단순 합).
