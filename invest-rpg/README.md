# 투자 RPG (가제)

모바일(iOS/Android)용 2D 픽셀 RPG풍 투자 시뮬레이션 게임.
감으로 투자하다 전 재산을 잃은 20대 후반 청년이 공부하고, 인형 눈 붙이기로 모은 1만 코인로 다시 시작하는 이야기.

**현재 단계: W1 — 게임 규칙 엔진** (화면·그림·결제·광고·서버 없음)
- 단계 A(엔진·스키마·테스트·시뮬레이션·점검 스크립트) 완료
- 단계 A 보완: 5번 반복 시뮬레이션으로 밸런스 조정, 규칙 검토(`docs/logic_review.md`), 플레이 데이터 수집 구조(`docs/telemetry.md`)
- 2차 결정 반영: 플레이 중 정보 숨김(공개용 뷰), 외부 유입 입금과 시간가중수익률, 세이브 버전 고정, 기록 동의, 단서 확률 65%
- 화면 단계 인계 사항: `docs/ui_handoff.md`
- 단계 B(2000년대 콘텐츠 재작성) 대기 중 → 그 전까지 `ALL_ERAS`는 비어 있다. 데모·시뮬레이션은 기획 조건을 흉내 낸 **가상 시대**로 돈다.

## 1. 실행 방법

1. [Node.js](https://nodejs.org) **22.18 이상** 설치 (Node.js = 컴퓨터에서 타입스크립트를 실행해 주는 프로그램)
2. `cd invest-rpg && npm install`

| 명령 | 하는 일 |
|---|---|
| `npm test` | 자동 테스트 전체 |
| `npm run sim` | 밸런스 시뮬레이션 (전략 10개 + 참고 2개 × 시드 200개). `npm run sim -- 50`으로 빠르게 |
| `npm run sim:repeat` | 반복 시뮬레이션: 서로 다른 가상 데이터·시드로 5번 × 200판, 평균·손실 확률·목표 판정 (약 3분) |
| `npm run sim:carry` | 3시대 연속 이월 시뮬레이션: 전략별 최종 자산 분포, 자산이 1,000코인 아래로 떨어진 비율 |
| `npm run telemetry:report` | 플레이 기록 분석 리포트 (봇 기록으로 점검, 또는 `-- 기록.jsonl`) |
| `npm run lint:content` | 콘텐츠 작성 가이드 점검 (영향 테마 수, 영향도 공식, 해설 누락, 분위기 편향, 종목명·뉴스 금지어 등) |
| `npm run demo` | 한 시대를 터미널에서 끝까지 (뉴스·해설 알림 출력). `npm run demo -- 7`은 시드 7 |
| `npm run demo -- tutorial` | 튜토리얼 흐름 |
| `npm run check` | 타입 검사 + 테스트 |

### 화면(W2 이후)에서 엔진을 쓰는 법

화면은 **공개용 뷰 `PublicGame`만** 쓴다 (`docs/ui_handoff.md`). 엔진 본체 `Game`은 뉴스의 영향 방향·테마 분위기 같은 숨김 정보를 들고 있다.

```ts
const game = PublicGame.create({ eras: ALL_ERAS, seed, locale: 'ko' });  // 시대 시작 때 테마 20개 추첨

// 화면 쪽 타이머가 5초마다 호출. 뉴스가 떠도 시간은 멈추지 않는다.
const r = game.advanceTick();
if (r.advanced && r.news) showNews(r.news);            // id·종류·제목·본문·발표 시각 (+결과 뉴스만 가상 시나리오 태그)
if (r.advanced) updatePrices(r.prices);                // 뉴스 발표 순간 반영분 포함
if (r.advanced) r.recaps.forEach(showRecap);           // 발표 120초 뒤: 발표 즉시 % · 5초 뒤 % · 합계 %
if (r.advanced && r.saveNeeded) persist(savePublicGame(save, game));   // 매매·뉴스·백그라운드·30초마다
if (r.advanced && r.settlement) showSettlement(r.settlement);           // 시간가중수익률, 순손익, 입금, 누적

game.getStockList();               // 즐겨찾기 먼저 + 가나다순. id는 판마다 바뀌는 무작위 문자열
game.buy(id, 3); game.sell(id, 1);
game.deposit(3000, 'work');        // 외부 유입: work(인형 눈) / purchase(결제) / ad(광고 보상) / other
game.suspend(); game.resume();     // 백그라운드·입력 없음
game.getEraDebrief();              // 시대가 끝난 뒤에만: 분위기·비중, 단서와 실제 결과, 해설 전체
game.startNextEra();               // 다음 시대 (자금 이월)

game.setConsent(true);             // 플레이 기록 동의 (기본 꺼짐)
game.track('news_popup', { newsId, dwellMs, closedBy: 'confirm' }, Date.now());

const r2 = restorePublicGame(save, ALL_ERAS);   // status: resumed / settled_on_version_change / restarted_legacy
const tut = new TutorialSession();               // 화면은 tut.view (공개용 뷰)
```

## 3. 데이터 구조

### 테마 (시대마다 풀 36개, 테마당 종목 1개)
```jsonc
{ "id": "semiconductor", "name": {"ko": "...", "en": "..."},
  "sentiment": "positive",        // positive 13 / negative 13 / neutral 10
  "relevance": "core",            // core 24 : peripheral 12 (분위기와 독립)
  "keywords": { "ko": ["반도체", "메모리", ...], "en": [...] },   // 5~8개
  "existsEvidence": "그 시대에 존재했다는 근거 한 줄 (모르면 '확인 필요')" }
```
- 비주류(peripheral) 테마는 주로 시장 전체 뉴스·간접 영향으로 움직이는 '배경 종목'이다. 뉴스 풀 전체에서 최소 2회는 영향 대상이어야 한다.
- 풀 크기는 코드에 고정하지 않고 데이터에서 읽는다.

### 종목 (테마당 1개, 가상 회사)
- 이름은 **"2글자 중립 수식어 + 업종"** (예: `평화 방산`, `온유 제약`). 업종 뒤에 '주'를 붙이지 않는다.
- 수식어는 색·사물·자연물처럼 중립적인 단어. 평가·전망 어감(최강, 폭등, 유망, 위기, 호황, 불황 등)은 금지.
- 설명은 제품·서비스 중심의 중립 서술. 전망·평가 표현(유망, 전망, 기대, 선도, 1위 등) 금지.
- 실존 기업명·상표·인물명 금지. 모두 `lint:content`와 테스트가 검사한다.

### 뉴스
```jsonc
{ "id": "...", "type": "breaking",   // breaking(속보) / tentative(잠정) / outcome(결과)
  "magnitude": 7,                     // 뉴스 규모: 속보 3~9, 잠정 1~3, 결과 7~9 위주
  "title": {...}, "body": {...},      // 본문에 연도·월 표기 금지
  "effects": [{
    "themeId": "refining", "impact": 7,
    "link": { "strength": 3,          // 3 직접 / 2 밀접 / 1 간접
              "keywords": [{ "newsTerm": "유가", "themeTerm": "정유" }],
              "chain": "강도 2·1일 때 연결 설명" },
    "reason": { "ko": "해설 알림용 한 줄 이유" },   // 영향도 절댓값 상위 4개는 한국어 필수
    "adjustNote": "공식에서 ±1 조정했을 때 이유" }],
  "realDate": "2008-07-11",           // 근거 확인용 메타데이터
  "reactionNote": {...} }             // 결과 뉴스가 반대로 반응할 때 (실제 기록 근거가 있을 때만)
```
- **영향도 공식**: `|impact| = max(1, round(magnitude × 계수))`. 계수는 강도 3 → 1.0, 2 → 0.6, 1 → 0.3이고, 부호는 호재/악재다.
- 제목·본문에 **주가 방향을 직접 알려주는 표현 금지**: 호재, 악재, 수혜, 수혜주, 타격주, 상승 예상, 하락 예상. 사건 자체의 표현("유가 급등")은 괜찮다.
- 영향 테마 6~9개. 호재와 악재를 섞는다. 분위기 편향(긍정 테마 호재 약 **75%**, 부정 테마 악재 약 75%, 중립 50%)을 맞춘다. (65% → 75%, 6장)
- 종류(direct/indirect)는 따로 적지 않고 강도에서 계산한다 (3 → direct, 2·1 → indirect).

### 스토리 (잠정 → 결과)
```jsonc
{ "id": "...", "tentative": { /* 잠정 뉴스 */ },
  "news": [ /* 결과 2개 (+ 단서) */ ],
  "outcomes": [ { "newsId": "A", "isHistorical": true }, { "newsId": "B", "isHistorical": false } ],
  "leansTo": "A",                    // 잠정 뉴스 본문의 단서가 가리키는 결과
  "clues": [ { "newsId": "...", "pointsTo": "A" } ] }   // 선택
```
- 결과는 **항상 서로 반대인 2개**다 (공통 테마의 부호가 반대). 검사기가 확인한다.
- 결과는 그때그때 추첨한다. 단서(`leansTo`)대로 **65%**, 반대로 35%다 (`LEAN_PROB`, 6장 참고).
- 추천: 단서 쪽 결과를 실제 역사(`isHistorical: true`)로 맞춘다 (`docs/logic_review.md` B5).
- 잠정 뉴스 본문은 결과를 확정처럼 쓰지 않고, 판단 단서가 읽히게 쓴다.

## 4. 확정된 규칙

| 항목 | 값 |
|---|---|
| 상수 | `TICK_SECONDS=5`, `MAX_TICK_MOVE=1.5`, `WINDOW_TICKS=12`, `WINDOW_CAP=3.0`, `NEWS_REACTION_TICKS=1`, `INERTIA_TICKS=2`, `INERTIA_PROBS={50,25,25}`, `NEWS_BAND_PCT=30`, `P_START_STORY=0.85`, `LEAN_PROB=0.65`, `INSTANT_REACTION_SHARE=0.75`, `AUTOSAVE_SECONDS=30` |
| 시간 | 시대당 2시간(1,440틱), 3시대 총 6시간, 차트 20분(240개), 게임 모드는 하나(실전) |
| 시대 시작 추첨 | 테마 풀에서 20개 (긍정 7 / 부정 7 / 중립 6), core 11개 이상, 속보 10·스토리 8 이상 사용 가능해야 함 (최대 50회 재추첨) |
| 일반 변동 | 틱당 -1.5~+1.5%, 1분 누적 ±3%, 넘치면 반사 |
| 뉴스 시점 | 첫 뉴스 1~3분, 이후 4~7분 간격 (시대당 평균 약 22개, 최대 30슬롯) |
| 뉴스 구성 | 슬롯 기준 속보 약 1/3, 잠정 약 1/3, 결과 약 1/3 |
| 뉴스 반영 | 발표(틱 k) **순간 75%** → **틱 k+1(5초 뒤)에 나머지 25%** → k+2·k+3 관성 (같은 방향 50 / 반대 25 / 변동 없음 25) |
| 반영률 | 영향도 × 3% × 배율 (강도 3: 0.6~1.4, 강도 2·1: 0.4~1.6), ±30%로 자름 |
| 뉴스 사이 한도 | 발표 시점 가격 P0 기준, 다음 뉴스 전까지 [0.7×P0, 1.3×P0] (모든 움직임 포함) |
| 해설 알림 | 발표 120초 뒤, 반영률 상위 3종목 + 나머지 개수, 시간을 멈추지 않음 |
| 수수료 | 매수·매도 각 0.2% |
| 수익률 | **시대별 시간가중수익률**: 입금 때마다 구간을 나눠 (구간 끝 자산 ÷ 구간 시작 자산)을 곱한 뒤 − 1. 입금이 없으면 (최종 자산 − 시작 자금) ÷ 시작 자금과 같다. 누적 수익률 = 시대별 수익률의 곱 |
| 자금 | 시작 1만 코인, 시대가 바뀌어도 계속 이월. 외부 유입(인형 눈 붙이기·결제·광고 보상)은 `deposit`으로 |
| 정보 숨김 | 플레이 중 호재/악재 방향, 테마 분위기·비중을 보여주지 않는다 (모든 뉴스). 시대가 끝난 뒤 `getEraDebrief()`로 공개 |
| 튜토리얼 | 첫 진입 한 번. 뉴스 1개 → 매수 → 반영 확인 → 해설 알림. 이때만 뉴스가 뜨면 시간 정지 |
| 기본 OFF 옵션 | `ORDER_DELAY_TICKS=0`(주문 N틱 뒤 체결), `INDIRECT_EXTRA_DELAY_TICKS=0`(간접 영향 N틱 늦게) |

## 5. 가정한 규칙 (바꾸고 싶으면 알려주세요)

표시: 🆕 이번에 새로 정함 · ✏️ 이번에 바뀜 · ⚠️ 확정 규칙을 바꾼 것 (기획자 승인) · (표시 없음) 전과 같음

### 확정 규칙 변경 기록
- ⚠️ **뉴스 반영 시점** — 기존: 발표 5초 뒤 100% 반영 → 변경: **발표 즉시 75% + 5초 뒤 25%** (`INSTANT_REACTION_SHARE = 0.75`).
  이유: 기존 규칙에서는 뉴스를 보고 5초 안에 사면 영향 전부를 공짜로 얻어, 초고속 추종 전략이 시대당 **+536%**(몰빵 +889%)였다. 변경 후 +63%(목표 +30~80%). 기획자 승인.
- ⚠️ **잠정 뉴스 단서 확률** — 60%(첫 요청) → 65% → 70%(시뮬레이션 보정) → **65%**(기획 결정, `LEAN_PROB`).
  이유: 한 판에 같은 스토리는 한 번뿐이라 큰 수의 법칙이 약하게 작용하므로, 확신보다 분산 투자를 고르게 한다. 잠정 정방향 목표도 +25~100%로 낮춤.
- ⚠️ **수익률 공식** — 기존: (최종 자산 − 시작 자금) ÷ 시작 자금 (예전 연습 모드의 광고 보상 수익률 공식 포함) → 변경: **시대별 시간가중수익률**. 이유: 시대 중간 입금이 수익으로 잡히지 않게.

### 시대 시작 추첨
1. 분위기 그룹마다 따로 섞어서 앞에서부터 뽑는다(층화 추첨). 재추첨 시드는 원래 시드에서 시도 번호로 만든다.
2. 50회 안에 조건을 못 맞추면 "core 조건 충족 → 속보·스토리 충족 정도" 순으로 가장 나은 추첨을 쓰고, `draw.warning`에 경고를 남긴다.
3. 스토리는 잠정 뉴스와 결과 2개가 모두 유효(유효 영향 테마 3개 이상)해야 쓴다. 유효하지 않은 **단서** 뉴스는 빼고 스토리는 그대로 쓴다.
4. ✏️ 이번 판에서 뉴스의 영향은 활성 테마 것만 남긴다. (영향 테마는 플레이 중 화면에 보이지 않고, 시대 종료 후 공개에서만 보인다.)

### 뉴스 일정
5. **구성 비율 해석**: 빈 슬롯마다 진행 중인 스토리가 없으면 85% 확률로 새 잠정 뉴스를 시작하고, 아니면 속보를 넣는다. 그래서 슬롯 기준 **속보·잠정·결과가 각각 약 33%**가 된다. 기획의 "속보 : 잠정 = 1 : 2"를 이렇게 해석했다.
6. 속보가 바닥나면 스토리를, 스토리가 바닥나면 속보를 넣는다. 둘 다 없으면 그 슬롯은 비운다(반복 없음).
7. 단서 뉴스는 실제로 뽑힌 결과를 가리키는 것만, 잠정과 결과 사이 빈 슬롯에 나온다. 단서도 슬롯 하나를 차지한다.
8. ✏️ "가상 시나리오" 태그는 **결과 뉴스에만**, 발표된 뒤에 붙는다. (이전에는 가상 결과를 가리키는 단서 뉴스에도 붙였는데, 그러면 결과가 나오기 전에 "가상 쪽으로 간다"는 정답이 새어 나가서 뺐다.) 화면에서 단서 뉴스의 종류는 "잠정"으로 표시한다.
9. 마지막 뉴스는 반영·관성이 시대 안에서 끝나는 시점까지만 뜬다.

### 가격
10. 뉴스 사이 한도의 기준가(P0)는 뉴스가 발표되면 **모든 종목**에서 그 순간 가격으로 다시 잡힌다.
11. 한도 계산은 정수 가격 기준이다: 하한 = 올림(0.7×P0), 상한 = 내림(1.3×P0).
12. 일반 변동은 1분 한도와 뉴스 사이 한도를 둘 다 만족하도록 반사한다.
13. 뉴스 반영이 한도에 막혀 0%가 되어도, 관성 방향은 원래 반영 방향을 따른다.
14. 관성 크기는 0.1~1.5%이고 1분 한도에서 제외한다. 뉴스 사이 한도 안으로만 반사한다.
15. **발표 즉시 몫**: 종목별 반영률을 0.1% 단위로 75%(0 쪽으로 버림)와 나머지로 나눈다. 나머지가 0이 되면 관성이 생기지 않으므로 최소 ±0.1%는 5초 뒤 몫으로 남긴다. 즉시 몫은 틱을 진행하지 않고 가격만 옮기며, ±30% 한도의 기준가는 즉시 몫 반영 **전** 가격이다.

### 해설 알림·보관함
16. 해설 알림의 종목은 이번 판 활성 종목 중 그 뉴스로 실제 반영이 일어난 종목이다. 반영률 절댓값 순 상위 3개를 보여준다.
17. ✏️ `appliedPct` = 발표 즉시분(`instantPct`) + 5초 뒤분(`delayedPct`)의 **단순 합**(0.1% 단위 변동률의 합, 복리 아님).
18. `reason`이 없는 항목은 자동 문구 재료(`auto`: 뉴스 단어, 업종 이름, 수혜/부담)를 넘긴다. 해설은 반영이 끝난 뒤라 방향 표현을 써도 된다.
19. 🆕 결과 뉴스가 예상과 반대로 반응한 이유(`reactionNote`)는 뉴스 팝업이 아니라 해설 알림과 시대 종료 후 공개에서만 보여준다.
20. 해설 알림 시점이 시대 마지막 틱과 같으면 만들고, 넘으면 만들지 않는다. 🆕 시대 종료 후 공개(`getEraDebrief`)에는 해설 알림이 없던 뉴스까지 **모든 뉴스의 해설 전체**(상위 3개 제한 없음)가 들어간다.

### 정보 숨김 (공개용 뷰)
21. 🆕 화면은 `PublicGame`만 쓴다. 뉴스는 id·종류·제목·본문·발표 시각(+결과 뉴스만 가상 시나리오 태그), 종목은 id·이름·설명·가격·즐겨찾기 등만 담는다.
22. 🆕 종목·뉴스의 공개 id는 `(게임 시드, 시대 id, 내부 id)`로 만든 무작위 문자열이다. 판(시드)마다 바뀌고, 내부 id·데이터 순서와 무관하다.
23. 🆕 종목 목록: 즐겨찾기 묶음이 먼저, 각 묶음 안은 이름 가나다순(한글은 유니코드 순서 = 가나다순, 영어는 소문자로 바꿔 알파벳순, 같으면 공개 id순).
24. 🆕 결과 뉴스와 그 잠정 뉴스의 연결은 플레이 중 공개용 뷰에 넣지 않았다 (요청한 공개 필드 목록에 없어서). 시대 종료 후 공개에는 들어간다. → 넣을지 질문 (`docs/logic_review.md` B7)
25. 🆕 시대 종료 후 공개는 `era-ended`·`finished` 상태에서만 된다. 진행 중·일시정지 중에는 오류.

### 입금·수익률
26. 🆕 `deposit(금액, 출처)`: 금액은 1 이상의 정수, 출처는 `work`·`purchase`·`ad`·`other`. 일시정지 중에도 넣을 수 있다.
27. 🆕 시대 진행 중 입금: 입금 직전 총자산(현재가 기준)으로 구간을 닫고, 입금 뒤 자산으로 새 구간을 연다. 구간 시작 자산이 0이면 그 구간은 건너뛴다.
28. 🆕 시대가 끝난 뒤(정산 후, 다음 시대 시작 전) 입금: 현금만 늘고 **다음 시대 시작 자금**에 들어간다. 끝난 시대의 수익률·입금 합계에는 넣지 않는다.
29. 🆕 순손익(`profitAmount`) = 종료 자산 − 시작 자금 − 이번 시대 입금 합계. 누적 수익률 = 시대별 수익률 (1 + r)의 곱 − 1.

### 세이브
30. ✏️ 세이브에 담는 것: 시드, 시대 순번·id·순서값, 그 시대 시작 자금, 추첨 결과, 지난 시대 수익률, 이번 시대 행동(매매·입금), **버전(엔진·콘텐츠·밸런스)**, **상태 스냅샷(틱, 종목 현재가, 현금·보유 종목·종목별 성과, 즐겨찾기, 수익률 진행)**, 상태 지문, 기록 동의 여부.
31. 🆕 **콘텐츠 버전**은 직접 적는 번호가 아니라 시대 데이터 전체의 지문(해시)으로 자동 계산한다 (글자 하나만 바뀌어도 다름 → 올리는 걸 잊을 일이 없음). **밸런스 지문**(설정값 지문)도 버전 비교에 넣었다. 설정이 바뀌면 같은 시드라도 가격이 달라지기 때문.
32. 🆕 불러오기: 버전이 모두 같으면 리플레이 후 상태 지문까지 같아야 `resumed`. 버전이 다르면 스냅샷 가격으로 전량 청산(수수료는 지금 설정 기준)해 그 시대를 정산하고 다음 시대부터 새 버전으로 `settled_on_version_change`. 같은 버전인데 리플레이 결과가 스냅샷과 다를 때도 같은 방식으로 정산(`reason: 'replay-mismatch'`).
33. 🆕 이미 정산이 끝난 시대에서 저장했다면 버전이 달라도 다시 정산하지 않고 다음 시대로 넘어간다. 마지막 시대였으면 다음 게임 없이(`game: null`) 정산 결과만 돌려준다.
34. 🆕 다음 시대는 저장된 시대 id의 다음 순서로 찾고, 그 id가 새 데이터에 없으면 저장된 순서값(`order`)보다 큰 첫 시대로 한다. 새 시대는 추첨을 새로 한다.
35. 🆕 옛 형식(버전 1) 세이브는 그 시대를 새 시드로 처음부터 시작한다(`restarted_legacy`). 출시 전 개발용 세이브만 해당.
36. 🆕 저장 필요 신호(`pendingSaveReasons`): 매매, 입금, 뉴스 발표, 백그라운드 전환(`suspend`), 마지막 저장 후 30초(6틱) 경과, 시대 종료. 화면은 신호가 있으면 저장하고, `saveGame`이 신호를 비운다. 즐겨찾기 토글만으로는 신호가 나지 않는다(다음 30초 저장에 함께 담김).

### 기타
37. 튜토리얼은 5분짜리 판이다 (뉴스 30초, 해설 알림 2분 30초). 뉴스로 시간이 멈춘 동안에도 매매할 수 있다. 즉시 몫은 뉴스가 뜨는 순간(시간 정지 전) 반영된다.
38. 주문 지연 옵션을 켜면 주문은 접수만 되고 N틱 뒤 그 틱의 가격으로 체결된다 (기본 꺼짐).
39. 평균가는 이동평균, 수수료는 내림이며 매입원가에 포함, 구입 순서 보존, 매수 시 즐겨찾기 자동 추가.
40. ✏️ 플레이 기록은 **기본 꺼짐**. `setConsent(true)` 뒤에만 기록을 내보낸다(기록 통을 붙여도 동의 전엔 없음). 판 도중 동의하면 그때까지의 행동을 `game_start`에 담아 리플레이할 수 있게 한다. 동의를 끄면 즉시 멈춘다.

- 발표 즉시 몫 선택: 0% → 초고속 추종 +537%, 60% → +113%, 70% → +77%, **75% → +62%**, 80% → +48% (5번 × 100판 평균).

### 남은 주의점
- **판마다 편차가 크다**: 지연 추종 하위 10% -31%, 상위 10% +40%. 실력보다 운이 크게 느껴질 수 있다 → 실제 기록으로 체감 확인 (`docs/telemetry.md` 4장).
- 시뮬레이션 봇은 사람과 다르다. 실제 플레이 기록으로 다시 맞춰야 한다 → 수집 구조는 `docs/telemetry.md`, 결정 기록은 `docs/logic_review.md`.
